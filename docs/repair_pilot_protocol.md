# 修复干预预检：冻结协议

本轮仅用本地 Qwen2.5-0.5B-Instruct base，无 API、适配器训练、论文修改或测试后调参。配置：`configs/repair_pilot_v1.json`。

## 数据与预算

六种既有合成模板各 16 道新题，排除第一、二阶段所有题目；每题分别在第 1/2 个计算步骤注入 ±1 结果错误，每个模板×位置内正负均衡。符号算术检查所有正确步骤与最终答案，只保留目标步骤及其之前的前缀，不提供最终答案或原后缀。seed=20261001。

- C：正确前缀＋正确目标步骤。
- B：相同前缀＋错误目标步骤。
- R：B 后追加 `Correction: the previous step was incorrect. It should be: {正确步骤}`。
- S：相同纠正句式，但重复错误步骤。它是主动假修复对照，不是中性的长度对照。
- F：不提供 assistant 前缀的自由生成，作为能力背景。

每个场景四条件各 8 次组成固定 32 条采样批次；两批独立随机种子。F 每批组装四题×8 次。总计 96 题、192 场景、432 批、13,824 条输出。两批编号 0/1；随机种子来自 SHA256(总种子:批次 ID)，整批是最小恢复单位，不能更改批次顺序或组成。部分失败批次按相同种子整批重跑，不混合未完成记录。

bf16、SDPA、batch32、temperature=.7、top_p=.95、top_k=0、512 新 token；单 GPU、eval 模式、无梯度。续写输入为既有统一 chat generation prompt 后直接追加 assistant 前缀的 token，不附 EOS 或新 user turn。不改变 precision、长度或模型来救援坏结果。CUDA/软件/硬件环境记录入 manifest；相同环境下重启复现，不声称跨不同 GPU/库版本逐位相同。

显存不足则记录失败并退出，不抢占其他 GPU 进程、不自动缩 batch。仅从新生成文本判分；记录输出 token IDs、完整输入前缀、输入 IDs 哈希、输出文本、EOS/截断、显式答案标志。数字提取沿用历史 verifier，同时报告显式答案率，不能把答对解释为正确推理。

## 冻结统计

主要对比 C−B、R−B、R−S；两位置保留题目内配对，按模板分层、题目聚类 bootstrap 10,000 次，每个主要区间使用 98.3333% 置信水平，对三项比较作 Bonferroni 调整。模型是固定 base，没有训练 seed 总体推断。

分别计算两个独立采样批次的场景收益，在模板×位置内分别去均值，再做跨批次 Spearman。聚类重采样时同时保留两位置与两批次并重新去均值，报告 95% 区间；常数收益或退化重采样导致区间不可计算时不得通过稳定性门槛。仅 R−S 的可复现性用于门槛，其他相关性为描述性。该相关性区间是探索性的投入门槛，不是与三个主比较共同控制错误率的确认性检验；去均值不消除题目难度等全部混杂。

决策按以下优先级执行：

1. 任一条件（包括 F）截断率 >5%：协议不可解释；数据/判分/哈希不一致直接验收失败，不能给出有效科学结论。
2. C 成功率 <20%：当前小模型能力不足。
3. 三个主区间下界均 >0，R−S 均值 ≥5pp，且 R−S 跨批次相关性区间下界 >0：值得后续研究，但不是训练效果证据。
4. 满足收益和幅度条件但不满足稳定性：有修复收益、未证明稳定异质性，不能支持自适应监督分配。
5. 其余：完整候选机制没有可靠支持；保留各比较的具体方向，不用总体标签抹去局部效果。

R 由程序提供正确修复，不是自主纠错；没有在错误恢复能力上训练模型。无论哪种结果，都不自动启动训练、调用 API 或扩规模。即使通过预检，也须用同数据 SFT、普通局部 DPO、固定预防/恢复混合及等预算对照检验后续新目标。

## 命令与验收

```bash
OMP_NUM_THREADS=4 .venv/bin/python -m pytest -q
.venv/bin/python scripts/repair_pilot.py prepare
.venv/bin/python -u scripts/repair_pilot.py rollout --gpu 3 --max-jobs 1
.venv/bin/python -u scripts/repair_pilot.py rollout --gpu 3
.venv/bin/python scripts/repair_pilot.py analyze
```

`prepare` 拒绝覆盖已有目的目录；冻结数据、配置、源码、模型、排除集哈希与源码快照。`rollout` 使用单 worker 文件锁及原子写入，完成批次先验证再跳过。`analyze` 要求全量 432 批，重建数据、逐题重新判分、验证文本与 token IDs、输入哈希、重复项、样本数和全部结果哈希后才生成统计与图。验收通过与科学门槛通过是不同概念。

公开文献核查单独记录，仅用于判断候选方向与已有方法的重合，不改写论文、不把预检当作原创性证据。
